# G.A.I. Agent Gateway — 2026-10-07\n\n## Purpose\n\nThe Agent Gateway provides a controlled integration boundary for multiple external ChatGPT/agent sessions interacting with one physical G.A.I. system.\n\nIt does **not** add a competing cognition loop.\n\n## Architecture\n\nExternal agents\n→ Agent Gateway\n→ validated request / conversation boundary\n→ G.A.I. V1\n\nG.A.I. remains authoritative for:\n\nSenses → Nervous System → Neural Workspace → CC-V1 → Action/Motor → Organs\n\nThe gateway is outside that loop.\n\n## Multi-agent contract\n\nEvery interaction carries:\n\n- agent_id\n- session_id\n- correlation_id\n- explicit G.A.I. context\n- capability permissions\n\nChat history is isolated by agent/session.\n\nCommand requests are serialized through the existing state/user_command.json boundary. The gateway never calls an output organ or motor primitive directly.\n\nG.A.I.'s UserCommandCell remains responsible for accepting or declining the requested move, sleep, or wake action.\n\n## Safety boundary\n\n- loopback-only listener by default (127.0.0.1:8766)\n- unknown agents denied by default\n- explicit per-agent chat/command permissions\n- command allowlist limited to the existing V1 user-command contract\n- persistent audit log at state/agent_gateway_audit.jsonl\n- persistent command queue at state/agent_gateway_queue.jsonl\n- no direct shell, organ, motor or kernel control endpoint\n\n## Endpoints\n\nGET /health\nGET /agents\n\nPOST /v1/chat\n\nExample body:\n\n{\n  "agent_id": "chatgpt",\n  "session_id": "dev-01",\n  "correlation_id": "optional-id",\n  "message": "Inspect the current G.A.I. state",\n  "gai_context": {}\n}\n\nPOST /v1/command\n\nExample body:\n\n{\n  "agent_id": "chatgpt",\n  "session_id": "dev-01",\n  "correlation_id": "optional-id",\n  "command": "move",\n  "reason": "External agent request"\n}\n\nThe response reports the eventual G.A.I. decision; an external agent cannot force agreement.\n\n## Relationship to Desktop Commander\n\nDesktop Commander remains a transport/control channel for the laptop.\n\nThe gateway is the higher-level logical arbitration layer. Multiple ChatGPT sessions can use the same physical machine without requiring multiple Desktop Commander device identities.\n\nDo not run multiple Desktop Commander Remote agents solely to obtain multiple logical ChatGPT sessions. Prefer one stable physical transport plus this gateway.\n\n## V1 scope\n\nThis integration layer is deliberately external to cognition and motor authority. It is suitable for development, diagnostics and controlled multi-agent interaction without changing the frozen V1 architecture.\n
