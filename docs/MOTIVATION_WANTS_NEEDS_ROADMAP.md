# G.A.I. Needs, Wants & Motivation Roadmap

Date: 2026-10-06
Status: architecture/planning

## Why this is needed

G.A.I. already has several important components:
- CoreNeeds for power, social, processing, energy, rest, sleep and storage pressure.
- Instincts for threat, hunger, social seeking, rest seeking, conservation, exploration and protection.
- Chemistry-like state for arousal/stress/reward-related modulation.
- Emotions including fear, anxiety, joy, pleasure, frustration, contentment, loneliness, sadness and fatigue.
- DriveState for explore, rest, interact and maintenance pressure.
- V1 CNS action scoring using curiosity, boredom, novelty, fatigue, stress and learned experience.

What is missing is a formal separation between the pressure that says something is lacking, the internally generated thing G.A.I. would like to bring about, and the process that decides which competing desire becomes behaviour.

## Target hierarchy

    BODY / ENVIRONMENT
         ↓
    NEEDS
         ↓
    INSTINCTS + CHEMISTRY
         ↓
    WANTS
         ↓
    MOTIVATION COMPETITION
         ↓
    ATTENTION + PREDICTION
         ↓
    ACTION
         ↓
    CONSEQUENCE
         ↓
    REWARD / ERROR
         ↓
    MEMORY + NEURAL PLASTICITY

The layers must remain distinguishable. A want is not a command, and motivation is not the same thing as action.

## 1. Needs

Needs are homeostatic or experiential deficits. They should be generated by body state and lived conditions rather than written as goals.

Initial needs:
- energy/power
- rest/sleep
- safety
- stimulation/novelty
- social contact
- interaction/agency
- environmental exploration
- maintenance/repair
- memory/storage pressure

Each need should have:
- current level
- preferred operating range
- deficit
- rate of change
- urgency
- satisfaction channels
- deprivation consequences

The important change is to model a need as a trajectory rather than a single scalar. A rising social deficit and a stable social deficit should not produce the same pressure.

## 2. Wants

A want is a short-lived candidate desired state generated from one or more active needs plus the current environment, memory, prediction and learned history.

Examples:
- social need + nearby social signal -> approach/contact want
- novelty deficit + salient movement -> investigate want
- rest deficit + low energy -> rest want
- boredom + available creative capability -> create/explore want
- memory/storage pressure + sleep state -> consolidate/archive want

Wants should be generated dynamically. The system should not contain a fixed list such as “always likes music” or “always wants to explore”.

Every want should carry:
- source needs
- target state
- supporting sensory context
- predicted satisfaction
- predicted cost
- urgency
- novelty
- confidence
- expiry/decay

## 3. Motivation

Motivation is the competition and arbitration process over wants.

A motivation score should combine:

    need deficit
    + urgency
    + expected need reduction
    + predicted reward
    + learned preference
    + novelty/interest
    - energy cost
    - threat
    - opportunity cost
    + context fit

This score is a pressure, not an instruction.

Multiple wants should coexist. The winning motivation should normally influence attention and action selection, while weaker motivations remain available and can win later as internal state changes.

## 4. Wants must be satisfiable

A want should declare how it could become satisfied.

Examples:

    want: rest
    satisfaction: rest debt decreases

    want: investigate
    satisfaction: uncertainty decreases / knowledge gain occurs

    want: interact
    satisfaction: successful environmental or social response

    want: create
    satisfaction: artifact completed + inspected + useful/novel outcome

This lets motivation learn from real consequences instead of rewarding activity for its own sake.

## 5. Motivation should influence attention

Attention and motivation must remain coupled but not identical.

Needs create pressure. Wants bias what matters. Salience determines what is noticeable. Attention decides what receives limited processing. Prediction estimates possible outcomes.

Therefore:

    motivation -> attention bias
    salience -> attention capture
    attention + motivation -> action candidates

A sudden dangerous signal can capture attention even when it does not match the current want. Conversely, a weak familiar signal may become interesting because a strong need makes it relevant.

## 6. Motivation should learn

The same want can produce different future motivation after different outcomes.

Example:

    investigate -> useful discovery -> stronger future investigate tendency
    investigate -> repeated dead end -> weaker tendency / strategy change

Learning must attach to the actual context and consequence.

This should connect to the existing ExperiencePolicy and NeuralFabric rather than creating another preference store.

## 7. Sleep and motivation

Sleep should change the internal balance of motivation without requiring CC instructions.

Duplication and stale pressure should be reduced during pre-sleep.

Dream should replay unresolved or high-value wants, their predicted outcomes and their consequences.

Sleep maintenance can:
- consolidate successful want/action relationships
- decay unsupported preferences
- revise predicted satisfaction
- create or remove weak motivation pathways
- rebalance long-term need sensitivities within safe bounds

Central Consciousness should not directly schedule each maintenance task.

## 8. Neural-fabric connection

The neural fabric should eventually route more than stimulus directly to action.

Preferred long-term form:

    need + context -> want
    want + attention -> action candidate
    action + consequence -> updated want value

Phase 1 of the neural fabric already records attended stimulus -> action relationships. Future elastic connections should allow:

    need -> want
    want -> attention bias
    want -> action
    context -> want selection

These routes should remain sparse, bounded and experience-shaped.

## 9. Implementation phases

### Phase A — Formal need model
[ ] Convert current CoreNeeds fields into explicit need objects with deficit, target range, urgency, rate and satisfaction channels.
[ ] Separate physical needs from experiential needs.
[ ] Add rate-of-change tracking.
[ ] Add deprivation and recovery curves.

### Phase B — Want generator
[ ] Add a Want object with source needs, target, context, expected benefit/cost, urgency, confidence and expiry.
[ ] Generate wants from current deficits and available environment/actions.
[ ] Allow multiple concurrent wants.
[ ] Remove/expire stale wants.

### Phase C — Motivation competition
[ ] Add a bounded motivation arbiter.
[ ] Score wants using deficit, urgency, predicted satisfaction, learned experience, novelty, cost and threat.
[ ] Keep motivation separate from action execution.
[ ] Record why the winning want beat the alternatives.

### Phase D — Need satisfaction
[ ] Define measurable satisfaction channels for each initial need.
[ ] Replace generic “activity is good” rewards with measured need reduction and useful consequence.
[ ] Add overshoot protection so a satisfied need does not remain permanently motivating.

### Phase E — Learning integration
[ ] Feed want/action outcomes into ExperiencePolicy.
[ ] Feed high-confidence repeated relationships into NeuralFabric.
[ ] Track want success by context.
[ ] Add strategy revision after repeated failure.

### Phase F — Sleep/dream integration
[ ] Replay recent and unresolved wants during dream.
[ ] Consolidate successful want/action pathways.
[ ] Decay unsupported pathways.
[ ] Allow safe mutation of motivation sensitivities during sleep.
[ ] Keep maintenance autonomous and below CC level.

### Phase G — Emergent long-term wants
[ ] Allow recurring experiences to create durable preferences without hard-coded personality.
[ ] Allow durable preferences to compete with immediate needs, but never bypass safety.
[ ] Measure whether persistent wants improve behaviour rather than simply increasing activity.

## 10. Safeguards

Motivation must never bypass:
- safety limits
- hardware permissions
- energy/resource limits
- action budgets
- sleep/lifecycle protection
- external tool permissions

The architecture should make it impossible for a learned want to directly execute a raw hardware command.

## 11. Validation plan

Every phase needs experiments.

Core metrics:
- number of active needs
- deficit trajectories
- wants generated per cycle
- want lifetime
- motivation entropy / dominance
- need reduction after action
- predicted vs actual want satisfaction
- repeated-failure strategy changes
- action diversity
- reward efficiency
- CPU and memory cost
- wake vs sleep changes

Key behavioural tests:

1. Remove an available satisfaction channel and verify the corresponding need rises.
2. Provide two competing satisfaction opportunities and verify motivation competition changes with need urgency.
3. Repeat a successful want/action pairing and verify future preference changes.
4. Repeat a failed pairing and verify the system eventually changes strategy rather than retrying forever.
5. Sleep the organism and verify motivation pathways consolidate/decay without CC micromanagement.

## Immediate implementation priority

Build Phase A and Phase B before adding more sophisticated planning.

The next useful milestone is not “make G.A.I. want everything”. It is to make the system able to say internally, through structured state, “something is missing”, “this could satisfy it”, “this alternative is more compelling”, and then learn whether it was actually satisfied.

## Architectural principle

**Needs create pressure. Wants propose direction. Motivation chooses pressure to pursue. Attention allocates processing. Cognition predicts. Action tests. Consequences teach. Sleep reorganises.**
